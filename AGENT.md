# AGENT.md - точка входа для агента

Если ты новый агент или сессия оборвалась, читай в таком порядке:

1. этот файл;
2. `docs/STATUS.md` - на чём остановились и какой следующий шаг;
3. `docs/PLAN.md` - этапы и критерии готовности;
4. `docs/reference/MECHANICS.md` - когда нужна конкретная механика или число.

## 1. Суть проекта

Своя VR-игра для Meta Quest 3 (без ПК) на Godot 4. Повторяет ядро механик ASTRONEER своим кодом
и своей графикой. Требования пользователя, с которых всё началось:

1. камера за спиной персонажа со свободным обзором головой;
2. управление контроллерами;
3. перемещение предметов движением контроллеров.

Пользователь - начинающий: базовое программирование, без опыта в игровых движках.
Объясняй простым языком, давай готовые команды, не пропускай шаги.

## 3. Правила работы

- После каждого законченного куска - коммит с понятным сообщением на русском.
- В конце сессии и перед долгим действием обнови `docs/STATUS.md`. Это единственное место,
  где хранится текущее состояние.
- Разделяй три уровня проверки: «написано», «собирается на GitHub», «проверено на шлеме».
  Сборка без ошибок не означает, что игра работает в шлеме.
- Этапы маленькие: один этап - одна проверка в шлеме.
- Не клади в репозиторий: файлы ASTRONEER и всё извлечённое из них, скриншоты и тексты с вики,
  токены, ключи, пароли, файлы `*.keystore`. Репозиторий открытый.
- Из вики бери факты и числа и пересказывай своими словами. Тексты страниц не копируй.
- Придуманные в оригинале названия (планеты, вымышленные вещества, имена оборудования) в игре
  заменяются своими. Обычные слова (смола, глина, кварц, медь) использовать можно.
- Внешний вид каждого объекта - отдельная запись в библиотеке моделей, чтобы модель менялась
  подменой файла (раздел 6).
- Не выдумывай API движка и плагинов. Если пишешь по памяти - пометь это в коде и в STATUS.

## 5. Сборка на GitHub Actions

- Запускается при каждом изменении в `game/` или в файле сборки, а также вручную (workflow_dispatch).
- Шаги: скачивает Godot и шаблоны экспорта, скачивает плагин OpenXR Vendors в `game/addons/`,
  ставит шаблон сборки Android в `game/android/`, импортирует проект, делает пробный запуск без
  шлема на 30 кадров, проверяет модели, рисует картинки моделей, экспортирует APK пресетом `Quest`.
- Сборка падает, если в логе импорта, пробного запуска или проверки моделей есть `SCRIPT ERROR`
  или `Parse Error`, если у какой-то модели нет геометрии, либо если APK не появился.
- Шаг с картинками необязательный: при сбое сборка идёт дальше.
- Результат: артефакты `astro-planet-debug-apk`, `model-previews` (картинки PNG каждой модели,
  четыре вида витрины, папка `glb` с моделями) и `build-logs`.
- Ключ отладочной подписи создаётся при первой сборке и хранится в кэше Actions. Если кэш пропадёт,
  подпись сменится, и APK не установится поверх старого: сначала
  `adb uninstall com.vano3667.astroplanet`.
- Версии заданы в начале `build.yml` (`GODOT_VERSION`, `VENDORS_TAG`). Менять их вместе с
  `config/features` в `game/project.godot`.

Агент с доступом к GitHub может: запустить сборку, посмотреть шаги и хвост лога задания.
Файлы из артефактов (картинки, `import.log`, `smoke.log`) облачному агенту недоступны - если
нужен текст, выведи его в лог задания командой `cat`. В логе шага «Check models» есть строка
на каждую модель (число деталей, вершин, размеры) и итог `MODELS_TOTAL`.

## 6. Модели

Как устроено:

- Модель - список деталей. Деталь - простая фигура с размером, положением, поворотом и цветом.
  Единицы - метры, ось Y вверх, перед модели смотрит в -Z, начало координат в центре основания.
- Конструкторы деталей в `model_library.gd`: `bx` коробка, `cy` цилиндр или конус, `sp` шар или
  эллипсоид, `cp` капсула, `dm` купол, `rg` кольцо. В `models.gd` есть `rb` - коробка с заданным
  радиусом скругления.
- Цвет детали - ключ палитры. Ключ, начинающийся с `glow_`, светится (не зависит от освещения).
  Ключ `tint` красится цветом ресурса из записи каталога.
- Другие скрипты обращаются только к `models.gd`: `get_parts(id)`, `get_color(key)`,
  `get_tint(key)`, `get_catalog()`. Если модель с таким id есть в `models.gd`, она заменяет
  одноимённую из `model_library.gd`.
- `model_builder.gd` склеивает детали в один меш с цветами в вершинах. Обычные коробки получают
  небольшое скругление автоматически.

Как добавить модель: написать функцию со списком деталей в `models.gd`, добавить ветку в
`get_parts`, добавить запись в `CATALOG_EXTRA` (id, название, номер кольца витрины 0-3).

Как заменить модель готовым файлом: положить `game/models/custom/<id>.glb` или `<id>.tscn`.
Код менять не нужно. Годятся свои модели и модели с лицензией CC0 (наборы Kenney Space Kit,
Quaternius Ultimate Space Kit - найдены поиском, файлы не смотрели). Двоичные файлы облачный
агент положить в репозиторий не может, это делает пользователь.

Чего агент не видит: как модели выглядят. Картинки смотрит пользователь в артефакте
`model-previews` и пишет замечания словами. Описания внешнего вида образца собирает локальный
агент по `TASK_APPEARANCE.md` в закрытом репозитории `astro-planet-research`
(папка `data/appearance/`).

## 7. Кто что может

Облачный агент (GitHub и веб-поиск): пишет код, сцены и документы; запускает сборку и читает её лог.
Запустить игру и увидеть картинку не может. Страницы сайтов не открывает, видит только краткие
выжимки поиска.

Пользователь или локальный агент на ПК: ставит APK на шлем, запускает, описывает увиденное,
присылает вывод `adb logcat`. Если у тебя нет доступа к шлему, не отмечай проверочные пункты
выполненными.

## 8. Особенности окружения пользователя (по записям прежних сессий, не перепроверялось)

- Профиль Windows называется `C:\Users\Иван`. Кириллица в пути ломала программы.
  Всё рабочее держать в папках без кириллицы (`C:\Projects`, `C:\Android`).
- Доступа к Google Drive пользователя и к его ПК у облачного агента нет.
- У пользователя есть другой проект на Godot (`Vano3667/HPGTA-Game`), то есть редактор, возможно,
  уже установлен - версию не уточняли.
